# Architecture

The Swift package has three production targets:

- `CallQuitsCore`: dependency-free close, identity, eligibility, and confirmation decisions retained from CallQuits.
- `MxltCore`: deterministic middle-scroll transitions/speed and session suspension policy.
- `MxltUtils`: SwiftUI/AppKit shell, saved settings, public macOS adapters, and feature lifecycle.

`MxltUtilsApp` owns the menu bar scene and one settings window. `UtilityModel` coordinates the current feature switches, global pause, independent sleep/display/session suspension, and permission refresh. It starts only enabled, trusted features. Settings changes are observed outside input callbacks; the quit adapter retains its own narrow configuration invalidation. A central half-second trust check runs in common run-loop modes only when at least one feature is enabled, including during menu tracking. Login status refreshes on app activation/settings use, separately from this timer.

`QuitModel` retains the tested CallQuits preference and bounded Activity behavior. Its `quit.*` keys live in mxlt-utils' own defaults domain. `ScrollModel` stores validated `scroll.*` settings and exclusions. `Shared/SystemServices.swift` contains native permission and login-item operations. Accessibility access is shared by both features; enabled choices remain independent of temporary suspension.

`CloseMonitor` retains the passive annotated-session tap and bounded worker-queue Accessibility implementation. It pins native event/application/window identities and validates again before graceful or force termination. Disabling removes its tap, local monitor, observers, and pending work. The original close-state safeguards and timing remain intact.

`MiddleScrollService` uses a filtering annotated-session tap for middle-button gestures. Its callback copies native routing evidence and updates the small gesture state; app/window validation and synthetic dispatch happen after the callback. Scroll output uses the original anchor and process. Window bounds/ownership/visibility are revalidated, and ambiguous targets fail closed. A short-click replay sends a complete tagged down/up pair after validation. No synthetic down remains held while waiting for input. A canceled held gesture temporarily retains a cleanup-only tap to consume its matching release; it accepts no new gestures while disabled and releases the tap after the physical button is up. Permission loss may prevent consuming that up; the app never intentionally holds a synthetic button while waiting for physical input.

The scrolling tap calls `CloseMonitor.cancelForAuxiliaryInput()` before suppressing an auxiliary press. Both adapters ignore the shared synthetic marker, so replay cannot create new close intent. For a captured middle press, the filter separately forwards the original event to the quit monitor and retains its generation receipt. Movement beyond the close gesture tolerance, scrolling, cancellation, or lifecycle changes invalidate it. Only posting the verified original short-click pair completes the receipt, using the original release. With scrolling disabled or excluded, the passive tap observes native middle down/drag/up itself. Native tab ancestry and a real close control are required; no page titles are read. Middle-click tabs remain last-window/graceful only.

The user-facing quit feature is named **Quit on Close**; target names, attribution, and preference keys are retained. A normal left click can also capture the official `AXCancelButton` of the recipient’s sole standalone `AXDialog` window. Complete `AXWindows` membership binds remotely hosted controls to that recipient. TextEdit also has a narrowly scoped compatibility path for its observed startup chooser: `AXStandardWindow` with identifier `open-panel`, and an enabled `CancelButton` directly under its `AXSplitGroup`. This chooser returns no value for the button’s `AXWindow` and the window’s `AXCancelButton`. Matching TextEdit bundle identity, native window/button PIDs, reciprocal parent/child membership, and the existing sole-window/no-document/no-sheet checks are required. If either optional window/Cancel attribute exists, conflicting identity is rejected. These identifiers describe the inspected layout, not a public API guarantee for every macOS version. Document-bearing windows, sheets, additional windows, missing metadata, and nonofficial buttons are rejected. The clicked modal dialog may remain during confirmation, but quit still requires its actual disappearance followed by stable empty snapshots. This path never inherits any-window or force-quit behavior. No generic windowless-app watcher is introduced. Ordinary wheel and trackpad events never enter the scrolling tap. See [scroll design](SCROLL-DESIGN.md) for target and event decisions.

TextEdit's hosted chooser sends native input to AppKit's Open and Save Panel service while WindowServer assigns the stamped window to TextEdit. A separate identity adapter admits this candidate only when the host bundle, exact system service bundle/executable, service PID and window owner agree; release must retain the same service PID and stamped window. The worker still requires the verified Cancel control. Ordinary mismatched recipients remain rejected. During confirmation, only TextEdit dialog cancellation can retry up to two `AXError.cannotComplete` reads. The recovery helper discards elapsed confirmation on every accepted retry, keeping the original deadline, observed-disappearance history and active window/sheet observers. Fresh reliable matching snapshots must then span a complete confirmation interval. Other errors and exhausted retries cancel normally.

The filtering tap also owns `InputTapPermissionWatchdog`, which checks trust and fresh filtering capability on a separate serial queue every 250 ms while the tap exists, including idle and cleanup-only periods. `InputTapPermissionProbe` checks a keyboard-only filtering mask because deleting an enabled Accessibility row can leave trust true. The probe is immediately disabled/invalidated without a run-loop source. Failed capability detaches the existing Mach port before asking the main thread to clear gesture/UI state. Callbacks fail open after watchdog invalidation. Timeout recovery uses that same queue for a fresh check, then verifies the original watcher identity and enabled state before re-enabling. Re-enable and posting operations serialize with detachment; an invalidated watchdog cannot resume or affect a replacement. Startup/retry also requires fresh capability, and Settings reports unavailable input access even when the trust flag is stale. Permission loss and app termination bypass the ordinary button-release drain entirely. Generated event sources explicitly permit mouse, keyboard and system events with a zero suppression interval. Polling intervals are requested cadences, not measured or guaranteed revocation-response latency.

## Adding a feature

Add a small settings model and a native service with explicit, idempotent start/stop/cancel. Put deterministic decisions in `MxltCore` only when they need independent testing. Give the feature a settings section and menu switch, then add its lifecycle to `UtilityModel`. Reuse permission/login helpers where applicable. Test cleanup, permission loss, and interaction with existing features. A third feature does not need a registry, dynamic loading, or a plugin protocol.

Public API references: [CGEvent](https://developer.apple.com/documentation/coregraphics/cgevent), [Accessibility](https://developer.apple.com/documentation/applicationservices/axuielement), and [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice). SMAppService keeps launch-at-login tied to the installed app identity without a bundled helper or user launch-agent edits.
