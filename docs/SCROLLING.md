# Middle-button scrolling

Hold the wheel, move beyond the dead zone, and keep the pointer displaced to continue scrolling. Returning to the anchor stops motion; release or Escape ends the gesture without momentum. Ordinary wheel and trackpad events are not subscribed to or modified. Modified middle presses (Shift, Control, Option or Command already held) remain native input; pressing a modifier or another key/button during scrolling cancels it.

## Smooth scrolling

Version 0.2.0 includes **Smooth scrolling**, enabled by default in Middle scrolling settings. It eases speed changes while the button is held; turning it off gives direct speed changes. This setting is retained across disable/relaunch, and changing it cancels an active gesture before restarting monitoring.

The pure motion policy integrates an exponential velocity response with a 55 ms time constant and retains fractional points for low-speed travel. Each axis stops immediately at zero, and direction reversals discard old-direction velocity and fractional travel. Returning to the dead zone, release, or cancellation clears all motion state. There is no momentum after stopping.

Output is requested at 60 Hz, subject to fresh target validation and run-loop scheduling. At most one current validation is pending; there is no extra AX work in input callbacks and no cached validation used to bypass the target checks. Each accepted step is capped at 1/30 second so delayed or skipped ticks cannot accumulate a catch-up burst. This is a scheduling target, not a measured frame-rate guarantee.

## Routing and click preservation

The active annotated-session Core Graphics tap copies original native recipient PID and WindowServer window ID. Missing native identity, nonregular applications, this app, and excluded processes bypass interception. Exclusion eligibility is cached outside the event callback and refreshed on application launch, termination and activation.

An accepted middle down is held back while the pure gesture policy classifies the press. App and exact-window validation runs after the event callback. A short unscrolled release produces a paired middle down/up at the original anchor, only after rechecking the pinned application, window owner, original bounds and topmost window at the anchor. Replay expires 250 milliseconds after release; intervening input cancels it. No replay occurs after scrolling, cancellation, a long hold, a moved/closed/covered target, or uncertain validation. If a target becomes unverifiable after its down was intercepted, that sequence is consumed rather than sent somewhere else.

Generated events use a private `CGEventSource` tagged before creation. Both replay halves preserve the initial down's native window-routing context using `CGEvent.copy()`, then replace its source with the tagged private source through public `setSource(_:)`. This also pins a release made just across a window edge to the initial recipient. Each half retains its button type, modifiers, click count, pressure and timestamp, and the original native source is not mutated. The copied down must already match the anchor; its location is never reassigned. In the running macOS 27 fixture, assigning even the same global point with `CGEventSetLocation` corrupted the recipient's local point to a sentinel outside the content area. Preserving the original native point restored view-level scroll delivery. Both features recognize the marker and ignore it as new intent. Before suppressing any auxiliary down, scrolling notifies CallQuits to cancel pending quit intent.

Scroll events also preserve the original native window context. The adapter changes the copied event type through public APIs and copies documented pixel/line/fixed-point delta fields from a standard scroll event, with no momentum and no modifier flags. Events go to the pinned PID at the original anchor, so moving across another window does not retarget scrolling. Window metadata is checked on a serial worker with at most one executing probe and one current pending probe. [Cancelled queued work items](https://developer.apple.com/documentation/dispatch/dispatchworkitem/cancel()) never begin AX work; an executing probe retains its timeout and its stale result is rejected. The 60 Hz timer exists only during a captured press. No AX messaging, window enumeration, or event posting occurs in the tap callback. Metadata lookups use public Core Graphics APIs and do not capture screen pixels. On macOS 27, Dock and Notification Center expose invisible full-display canvases ahead of ordinary windows. Only verified system process/layer pairs (`com.apple.dock`: 20; `com.apple.notificationcenterui`: 21) and exact display rectangles qualify for an exception, and a bounded system-wide AX hit at the anchor must still positively identify the original app. Interactive system UI hits, smaller system windows and ordinary covering windows cancel. Nested scroll routing remains the target app's normal hit testing at the anchor; there is no cross-app claim of a universal nested-view lock.

## Cleanup

Release stops the timer before deferred work. Generation checks reject stale validation or replay. Escape, other input, permission loss, pause/disable, sleep, session resignation, Space change and display configuration changes cancel current work. A small noninteractive anchor indicator is hidden on cancellation.

When a feature is disabled while its middle down is suppressed, a cleanup-only tap consumes the matching up before removing itself. It cannot start a new gesture or post more scrolling. A physical-button-state check detects a missing up, allowing a 200 ms drain interval so a queued native up can arrive first. No synthetic down is posted until a complete valid click pair is ready; loss of permission or shutdown therefore cannot leave a held synthetic button. macOS can remove event-filter permission immediately, so cancellation cannot promise interception of subsequent physical events after revocation.

## Research and compatibility boundaries

The implementation uses Apple's [annotated-session event tap](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate(tap:place:options:eventsofinterest:callback:userinfo:)), [process-targeted event posting](https://developer.apple.com/documentation/coregraphics/cgevent/posttopid(_:)), [pixel scroll events](https://developer.apple.com/documentation/coregraphics/cgevent), and [WindowServer metadata](https://developer.apple.com/documentation/coregraphics/cgwindowlistcopywindowinfo(_:_:)). These APIs establish routing mechanisms, not universal application compatibility. The SDK documents window bounds in global coordinates relative to the main display's upper-left corner; calculations keep these logical coordinates without backing-scale conversion.

Maintained-project reports informed the checks: LinearMouse's [middle-click preservation issue](https://github.com/linearmouse/linearmouse/issues/1237) motivates complete paired replay only after classification, and its [held-scroll cursor issue](https://github.com/linearmouse/linearmouse/issues/1367) makes visible pointer movement in browsers/Electron an explicit live-test item. No implementation was copied from those projects.

Native applications may reject process-posted scrolling, and some apps have their own middle-drag semantics. Add those apps to exclusions. Window movement, an overlay covering the anchor, changing Spaces or displays, or missing public metadata ends the gesture conservatively. Physical mouse behavior, nested view behavior, browser/Electron cursor movement and multiple-display scaling require separate live verification; unit tests and synthetic event construction do not prove them. See [TESTING.md](TESTING.md) for actual verification results.
