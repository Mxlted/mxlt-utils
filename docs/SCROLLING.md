# Middle-button scrolling

Hold the wheel, move beyond the dead zone, and keep the pointer displaced to continue scrolling. Returning to the anchor stops motion; release or Escape ends the gesture without momentum. Ordinary wheel and trackpad events are not subscribed to or modified. Modified middle presses (Shift, Control, Option or Command already held) remain native input; pressing a modifier or another key/button during scrolling cancels it.

## Distance and speed

Version 0.3.8 keeps fine control near the anchor and adds stronger acceleration beyond 200 points outside the dead zone. Moving back toward the anchor slows scrolling; holding the pointer still keeps the selected speed. At the default 1× setting, distances of 10, 100, 200, 400 and 600 points beyond the dead zone request 44, 800, 2,400, 16,000 and 48,000 points per second. The maximum is six times the previous 8,000-point-per-second limit. This is original tuning for rapid long-page navigation, not a claim of reproducing an exact Windows algorithm.

Acceleration depends on distance from the anchor, so reaching a monitor edge does not introduce a sudden speed jump. The speed slider multiplies the curve, with a shared cap of 48,000 points per second. The radial curve is `speed = min(48000, (d × (4 + d / 25) + max(0, d - 200)² / 5) × sensitivity)`, where `d` is distance beyond the dead zone. The extra term starts with zero value and slope, preserving a smooth transition. Horizontal, vertical and diagonal gestures share the same total-speed cap. Smoothing does not add momentum after stopping.

## Smooth scrolling

The continuous **Scroll speed** slider ranges from 0.2× to 10×, with a numeric readout and no step tick marks. It scales travel for a given pointer displacement, up to the shared 48,000-point-per-second ceiling. The control defaults to 1× and persists across relaunches. Smooth scrolling uses its fixed default response; earlier preview smooth-speed preferences are ignored.

Version 0.2.0 includes **Smooth scrolling**, enabled by default in Middle scrolling settings. It eases speed changes while the button is held; turning it off gives direct speed changes. This setting is retained across disable/relaunch, and changing it cancels an active gesture before restarting monitoring.

The pure motion policy integrates an exponential velocity response with a 55 ms time constant and retains fractional points for low-speed travel. Each axis stops immediately at zero, and direction reversals discard old-direction velocity and fractional travel. Returning to the dead zone, release, or cancellation clears all motion state. There is no momentum after stopping.

Version 0.3.0 schedules smooth output with an [NSScreen display link](https://developer.apple.com/documentation/appkit/nsscreen/displaylink(target:selector:)) on the display containing the original anchor, requesting that screen's maximum refresh rate. Moving the pointer does not switch displays. Direct-speed mode and unavailable-display fallback use a 60 Hz timer. A separate timer checks release and permission state even if display callbacks pause; cancellation releases the display link immediately.

Output remains subject to fresh target validation and run-loop scheduling. At most one current validation is pending; there is no extra AX work in input callbacks and no cached validation used to bypass the target checks. Travel uses elapsed time between accepted frames, so a skipped validation tick does not drop that interval's travel. Each accepted step is capped at 1/30 second with no backlog, and stopping resets the frame clock. These are scheduling policies, not measured frame-rate guarantees. Version 0.2.0 uses the earlier 60 Hz output timer.

## Routing and click preservation

The active annotated-session Core Graphics tap copies original native recipient PID and WindowServer window ID. Missing native identity, nonregular applications, this app, and excluded processes bypass interception. Exclusion eligibility is cached outside the event callback and refreshed on application launch, termination and activation.

An accepted middle down is held back while the pure gesture policy classifies the press. App and exact-window validation runs after the event callback. Normal windows, bookmark-folder menus, popups and floating panels can be targets; an elevated window level alone does not invalidate a click. A short unscrolled release produces a paired middle down/up at the original anchor, only after rechecking the pinned application, window owner, original bounds, original level and topmost window at the anchor. Replay expires 250 milliseconds after release; intervening input cancels it. No replay occurs after scrolling, cancellation, a long hold, a moved/closed/covered target, a changed window level, or uncertain validation. A dismissed menu never falls through to its parent browser window, and a covering submenu cannot replace the pinned menu. If a target becomes unverifiable after its down was intercepted, that sequence is consumed rather than sent somewhere else.

Display capture can expose the macOS cursor as an opaque WindowServer window at Apple's cursor level. Version 0.3.8 recognizes that surface only after verifying the owner's protected WindowServer executable path through public `proc_pidpath`, the exact `CGWindowLevelForKey(.cursorWindow)` level, and a fresh system-wide Accessibility hit on the original target app. The remaining window list must still prove the exact original window, bounds, level and coverage. Unknown owners, failed AX checks and real covering windows still cancel; there is no general exception for OBS or high-level overlays. Verification runs on the existing worker, outside input callbacks.

Generated events use a private `CGEventSource` tagged before creation. Both replay halves preserve the initial down's native window-routing context using `CGEvent.copy()`, then replace its source with the tagged private source through public `setSource(_:)`. This also pins a release made just across a window edge to the initial recipient. Each half retains its button type, modifiers, click count, pressure and timestamp, and the original native source is not mutated. The copied down must already match the anchor; its location is never reassigned. In the running macOS 27 fixture, assigning even the same global point with `CGEventSetLocation` corrupted the recipient's local point to a sentinel outside the content area. Preserving the original native point restored view-level scroll delivery. Both features recognize the marker and ignore it as new intent. Before suppressing any auxiliary down, scrolling notifies CallQuits to cancel pending quit intent.

Scroll events also preserve the original native window context. The adapter changes the copied event type through public APIs and copies documented pixel/line/fixed-point delta fields from a standard scroll event, with no momentum and no modifier flags. Events go to the pinned PID at the original anchor, so moving across another window does not retarget scrolling. Window metadata is checked on a serial worker with at most one executing probe and one current pending probe. [Cancelled queued work items](https://developer.apple.com/documentation/dispatch/dispatchworkitem/cancel()) never begin AX work; an executing probe retains its timeout and its stale result is rejected. The 60 Hz timer exists only during a captured press. No AX messaging, window enumeration, or event posting occurs in the tap callback. Metadata lookups use public Core Graphics APIs and do not capture screen pixels. On macOS 27, Dock and Notification Center expose invisible full-display canvases ahead of ordinary windows. Only verified system process/layer pairs (`com.apple.dock`: 20; `com.apple.notificationcenterui`: 21) and exact display rectangles qualify for an exception, and a bounded system-wide AX hit at the anchor must still positively identify the original app. Interactive system UI hits, smaller system windows and ordinary covering windows cancel. Nested scroll routing remains the target app's normal hit testing at the anchor; there is no cross-app claim of a universal nested-view lock.

## Cleanup

Release stops the timer before deferred work. Generation checks reject stale validation or replay. Escape, other input, permission loss, pause/disable, sleep, session resignation, Space change and display configuration changes cancel current work. A small noninteractive anchor indicator is hidden on cancellation.

When a feature is disabled while its middle down is suppressed, a cleanup-only tap consumes the matching up before removing itself. It cannot start a new gesture or post more scrolling. A physical-button-state check detects a missing up, allowing a 200 ms drain interval so a queued native up can arrive first. No synthetic down is posted until a complete valid click pair is ready; the app never intentionally holds a synthetic button while awaiting input. macOS can remove event-filter permission immediately, so cancellation cannot promise interception of subsequent physical events after revocation.

Permission loss and app termination use immediate teardown instead of waiting for that drain. A background watchdog checks trust and fresh filtering capability every 250 ms even while idle or the main thread is busy. Deleting an enabled Accessibility entry can leave the trust flag true, so trust alone is insufficient. The capability probe creates a keyboard-only filtering tap and immediately disables/invalidates it, without installing a run-loop source or posting input. Failed creation is treated conservatively as unavailable input access, including failures whose precise OS cause is unknown. After a failed check the watchdog disables and invalidates the existing tap before scheduling main-thread cleanup.

Already queued callbacks pass input through, stale validations cannot post output, and timeout recovery must pass a fresh background capability check before its single re-enable attempt. Startup/retry requires the same check. Recovery results from a stopped or replaced tap are ignored. Click replay also checks current trust immediately before posting. Both replay calls are serialized against watchdog detachment, though macOS can still revoke permission during system event delivery. No claim is made that a posted pair is delivered atomically, or that the requested polling interval guarantees a response deadline. See [research and reference decisions](PROVENANCE.md#accessibility-entry-deletion-research).

Generated event sources explicitly permit all local mouse, keyboard and system input in both suppression states and set their suppression interval to zero. This is a defensive policy, not proof that Quartz's default filters caused the reported input problem. These source-specific APIs do not change global system settings. See Apple's [event-source filters](https://developer.apple.com/documentation/coregraphics/cgeventsource/setlocaleventsfilterduringsuppressionstate(_:state:)) and [suppression interval](https://developer.apple.com/documentation/coregraphics/cgeventsource/localeventssuppressioninterval).

## Research and compatibility boundaries

The implementation uses Apple's [annotated-session event tap](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate(tap:place:options:eventsofinterest:callback:userinfo:)), [process-targeted event posting](https://developer.apple.com/documentation/coregraphics/cgevent/posttopid(_:)), [pixel scroll events](https://developer.apple.com/documentation/coregraphics/cgevent), and [WindowServer metadata](https://developer.apple.com/documentation/coregraphics/cgwindowlistcopywindowinfo(_:_:)). These APIs establish routing mechanisms, not universal application compatibility. The SDK documents window bounds in global coordinates relative to the main display's upper-left corner; calculations keep these logical coordinates without backing-scale conversion.

Maintained-project reports informed the checks: LinearMouse's [middle-click preservation issue](https://github.com/linearmouse/linearmouse/issues/1237) motivates complete paired replay only after classification, and its [held-scroll cursor issue](https://github.com/linearmouse/linearmouse/issues/1367) makes visible pointer movement in browsers/Electron an explicit live-test item. No implementation was copied from those projects.

Native applications may reject process-posted scrolling, and some apps have their own middle-drag semantics. Add those apps to exclusions. Window movement, an overlay covering the anchor, changing Spaces or displays, or missing public metadata ends the gesture conservatively. Physical mouse behavior, nested view behavior, browser/Electron cursor movement and multiple-display scaling require separate live verification; unit tests and synthetic event construction do not prove them. See [TESTING.md](TESTING.md) for actual verification results.
