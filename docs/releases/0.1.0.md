# 0.1.0 — First preview

mxlt-utils is a native macOS menu bar app with two independently enabled features:

- **CallQuits:** the existing verified-close behavior, including red-button, native tab-close and Command-W support, save/cancel and remaining-window protection, editable exceptions, and optional Shift-click force quit.
- **Middle scrolling:** hold the mouse wheel and move from the anchor for proportional vertical, horizontal or diagonal scrolling. Return to the dead zone, release, or press Escape to stop. Short clicks remain usable, including opening browser links in a new tab.

Includes compact native settings, global pause, permission status/recovery, optional launch at login, app exclusions, and an original icon. Features start off, preferences are separate from standalone CallQuits, and there are no accounts or telemetry.

## Install

Download the Apple silicon (`arm64`) DMG and drag mxlt-utils into Applications. Launch that copy, enable a feature, then grant its own Accessibility access when requested. Do not run two quit monitors together. The app and DMG are Developer ID signed, notarized and stapled; `SHA256SUMS.txt` covers the finalized DMG.

Requires macOS 14 or later. Runtime verification was on Apple silicon with macOS 27.0.1. Xcode 16.4 CI builds/tests independently of release credentials.

## Verified for this preview

- 157 automated XCTest cases cover retained quit safeguards, gesture decisions, settings, native routing, tagging and lifecycle policy.
- Synthetic native input through the running Release app passed AppKit fixture checks for actual view-level middle clicks; continuous, diagonal and nested scrolling; original-window pinning; dead-zone/release/Escape stops; held pause/disable cleanup; repeated toggle cycles; and unchanged ordinary wheel input.
- Quit fixtures passed graceful last-window close, canceled native save prompts, replacement windows, minimized remaining windows, native tabs and Command-W.
- Chrome 156.0.8078.47, using a disposable local profile, passed one-tab middle-click preservation, continuous outer/nested scrolling, pointer-position preservation, dead-zone/release and Escape cancellation, without leaked middle clicks.
- Settings inspection, denied permission followed by user-granted recovery, and launch-at-login registration/unregistration were exercised.

These are automated and synthetic running-app checks, not physical mouse testing. See [the testing record](../TESTING.md) for methods and evidence boundaries.

## Known limits

Physical mice, mixed-scale displays, sleep/lock and midgesture permission revocation, older macOS runtimes, Intel runtime, separate-account installation, live Discord and broader Electron/application compatibility still need testing. The preview therefore publishes only the built arm64 architecture. Applications can impose their own axis locking or reject process-targeted input; add incompatible middle-drag apps to exceptions. Incomplete Accessibility data prevents quitting rather than relaxing verification.

The original target must remain verifiable and unobscured. Moving/hiding/closing that window or covering the anchor cancels scrolling. A stationary middle hold longer than half a second is consumed. Other input remappers can affect compatibility; test in isolation when diagnosing input behavior.
